# Operations reference

> Generated by `cargo xtask docs` from `crates/stetdoc-core/src/api/op_spec.rs`. Do not edit by hand.

There are 19 operations. A batch names the base token it was written against and lists operations, which apply completely or not at all. Every operation is a JSON object with an `op` field, and an unknown field is refused. A range inside a paragraph is `find` (which must match once, or `occurrence` says which match) or `start` and `end` (offsets in the paragraph's Final text, in Unicode scalar values unless the edit asks for UTF-16 units), or nothing for the whole paragraph.

## Block text

Block text is the same batch without JSON escaping. The grammar is provisional until the format experiments settle it.

```text
base: 3f9a0c11d2b4e577:7:51ac09f2e8b34d11
---
@replace
ref: p42
find: the Supplier shall
with: the Supplier must
---
@insert
ref: p42
place: after
paragraphs: <<END
A first new paragraph.
A second one.
END
```

A stanza starts with `@name`. A field is `key: value` on one line, or `key: <<TAG` and the lines up to a line that is exactly `TAG`. A key that is not a field of the operation is refused. What a newline means depends on the kind of the field:

| Kind | One line | Heredoc | A newline inside the value |
|---|---|---|---|
| text | everything after the first `: ` | the lines, joined by a newline | only in a heredoc |
| list | one entry | one entry for each line | never inside an entry |
| ref, choice, number, bool | the value | not allowed | never |

## `replace`

Replaces a text range, or the whole paragraph, with new text. The difference is made word by word.

Tracked as revisions: yes. Reversible by rejecting what it wrote: yes.

| Field | Kind | Required | Meaning |
|---|---|---|---|
| `ref` | ref | yes | The paragraph. |
| `with` | text | yes | The new text. A newline is a line break inside the paragraph, and a tab is written as a tab. |
| `find` | text | no | The text to find in the paragraph's Final text. It must match once, or `occurrence` says which match. A newline matches a line break of the paragraph. |
| `occurrence` | number | no | Which match of `find` to use, counted from 1. |
| `start` | number | no | The first character of the range, as an offset in the Final text. Not with `find`. |
| `end` | number | no | One past the last character of the range, as an offset in the Final text. Not with `find`. |

```json
{"op":"replace","ref":"p42","find":"shall","with":"must"}
```

## `insert`

Inserts new paragraphs before or after a paragraph or a table, in order.

Tracked as revisions: yes. Reversible by rejecting what it wrote: yes.

| Field | Kind | Required | Meaning |
|---|---|---|---|
| `ref` | ref | yes | The paragraph or table the new paragraphs go next to. |
| `place` | choice | yes | Whether they go before or after it. One of `before`, `after`. |
| `paragraphs` | list | yes | The paragraphs, in order. Each is one paragraph of text, and a newline inside one is a line break of that paragraph. In JSON an entry may be an object with a text and a style, and in block text one style applies to all. |

```json

```
